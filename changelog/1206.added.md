`fit()` can now expand a column holding a datetime dtype (`datetime64`, tz-aware, or `period`) into calendar features (year, month, day, weekday, ...) via `skrub.DatetimeEncoder`, behind a new `InferenceConfig.TRANSFORM_DATES` flag that defaults to `False`. Datetime columns are only accepted with the flag on: with it off, `fit()` raises a `TabPFNValidationError` naming the columns and the flag, where it previously crashed with an opaque numpy dtype-promotion error. A `timedelta64` column is always read as its length in seconds. A string column that merely looks like a date is read as a plain category or text, regardless of the flag.
