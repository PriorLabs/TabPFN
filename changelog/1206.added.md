New `InferenceConfig.TRANSFORM_DATES` flag (default `False`): with it on, `fit()` expands datetime columns (`datetime64`, tz-aware, or `period`) into calendar features via `skrub.DatetimeEncoder`; with it off, they raise a `TabPFNValidationError` naming the flag instead of an opaque numpy error. `timedelta64` columns are always read as seconds. Date-like strings stay plain categories or text. Not supported by the fine-tuning estimators.
