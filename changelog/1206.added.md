`fit()` can now expand a column holding a genuine datetime dtype (`datetime64`, tz-aware, or `period`) into calendar features (year, month, day, weekday, ...) via `skrub.DatetimeEncoder`, behind a new `InferenceConfig.TRANSFORM_DATES` flag that defaults to `False`. With the flag off, behavior is unchanged: a date is silently read as a plain category or text and `fit()` warns about it by name. A string column that merely looks like a date is always read as a plain category or text, regardless of this flag.
