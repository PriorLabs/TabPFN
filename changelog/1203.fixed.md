`fit()` no longer crashes the interpreter outright on some tables. Modality detection and predict-time dtype coercion both called `pandas.to_numeric` directly on a column; on some pandas/numpy versions that function has a signed 32-bit integer overflow in its scientific-notation parser, which segfaults on a string like `"8e2569614270"` (mantissa `8`, exponent in `[2**31, 2**32)`). Parsing now goes through Python's built-in `float`, one value at a time, which does not share the bug.
