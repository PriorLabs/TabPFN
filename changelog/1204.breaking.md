The loss criterion is now chosen from the task the estimator asked for rather than inferred from `max_num_classes`, so a multitask checkpoint carrying both a classification and a regression head can back `TabPFNRegressor` as well as `TabPFNClassifier`. `load_model` gains a required `which` argument and `get_loss_criterion`'s signature changes accordingly. Loading a regression checkpoint into `TabPFNClassifier` now raises instead of silently building an unused bar distribution.
