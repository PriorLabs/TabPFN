`InferenceConfig.N_ESTIMATORS` lets a checkpoint declare how many estimators to run. `n_estimators="auto"` (already the default) now takes that count instead of a hard-coded 8; passing an integer still overrides it, though naming a count through both `n_estimators` and `inference_config` now raises. Existing checkpoints lack the field and fall back to its default of `DEFAULT_N_ESTIMATORS=8`, so nothing changes for them, and feature-coverage scaling still raises the checkpoint's count on very wide tables. Ensembling checkpoints that declare different counts raises and asks for one to be passed explicitly.
