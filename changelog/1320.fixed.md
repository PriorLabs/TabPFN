Keep classifier polynomial preprocessing disabled on the differentiable-input path so gradients remain connected through an upstream PyTorch encoder.

`TabPFNRegressor` already disabled polynomial features on the same path, but that is a current implementation detail rather than a guaranteed one. If the regressor is later changed to honour a configured polynomial setting, gradient-based workflows will break at that point instead of gradually, so verify the `differentiable_input` path of both estimators before depending on it.
