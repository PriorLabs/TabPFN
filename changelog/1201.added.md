`fit()` can now expand date columns and encode text columns into numeric features instead of leaving them to the ordinal encoder. A column of `"39.00"` is read as a number regardless of the settings below, always: `detect_feature_modalities` already recognized such a column as numeric, but the value itself was never parsed, so it used to reach the model ordinal-encoded by alphabetical rank rather than by its actual value. A date-like string column is recognized the same way, and, when `USE_DATES` is on, expanded into the year, the day of year, the seconds since epoch and cyclical month, day and weekday pairs, using [skrub](https://skrub-data.org)'s `DatetimeEncoder`, which becomes a dependency. A `TEXT` column (a string column above `MIN_CARDINALITY_FOR_TEXT` distinct values that isn't a date) is, when `USE_TEXT` is on, encoded the same way with skrub's `StringEncoder`, tf-idf over character n-grams followed by a truncated SVD. Numeric columns and low-cardinality strings are passed through, so categorical detection and encoding are unchanged.

Four new `InferenceConfig` fields control the opt-in parts, since checkpoints can each decide what they need: `USE_DATES` and `USE_TEXT`, both `False` for now, so date expansion and text encoding stay opt-in until they have run more broadly; `MIN_CARDINALITY_FOR_TEXT` (default 40), the number of distinct values above which a string column is text rather than a category, a decision independent of `MAX_UNIQUE_FOR_CATEGORICAL_FEATURES`, which governs numerical-vs-categorical instead; and `TEXT_N_COMPONENTS` (default 30), how many numeric features each text column is encoded into. The fitted `DatetimeEncoder`/`StringEncoder` instances are available on the estimator as `expansion_encoders_`, keyed by their original column index.

`fit()` warns when it finds date columns and `USE_DATES` is off, so an opted-out date column is not reported only as free text.
