`fit()` now handles datetime and text columns instead of leaving them to the ordinal encoder. Columns are given the type their contents imply before validation, using [skrub](https://skrub-data.org), which becomes a dependency: a column of `"39.00"` arrives as a number, a datetime column is expanded into the year, the day of year, the seconds since epoch and cyclical month, day and weekday pairs, and a text column is encoded with tf-idf over character n-grams followed by a truncated SVD. Numeric columns and low-cardinality strings are passed through, so categorical detection and encoding are unchanged. Four new parameters control it: `use_dates` and `use_text`, both `True`; `text_cardinality_threshold` (default 30), the number of distinct values above which a string column is read as text rather than as a category; and `text_n_components` (default 30), how many numeric features each text column is encoded into. The fitted converter is available on the estimator as `input_converter_`.

`fit()` warns when it finds date columns and `use_dates` is off, so an opted-out date column is not reported only as free text.
