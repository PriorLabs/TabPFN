`fit()` can now expand datetime columns and encode text columns instead of leaving them to the ordinal encoder. Columns are given the type their contents imply before validation, using [skrub](https://skrub-data.org), which becomes a dependency: a column of `"39.00"` arrives as a number regardless of the settings below, a datetime column is expanded into the year, the day of year, the seconds since epoch and cyclical month, day and weekday pairs, and a text column is encoded with tf-idf over character n-grams followed by a truncated SVD. Numeric columns and low-cardinality strings are passed through, so categorical detection and encoding are unchanged. Four new `InferenceConfig` fields control it, since checkpoints can each decide what they need: `USE_DATES` and `USE_TEXT`, both `False` for now, so date expansion and text encoding stay opt-in until they have run more broadly; `MIN_CARDINALITY_FOR_TEXT` (default 30), the number of distinct values above which a string column is read as text rather than as a category; and `TEXT_N_COMPONENTS` (default 30), how many numeric features each text column is encoded into. The fitted converter is available on the estimator as `input_converter_`.

`fit()` warns when it finds date columns and `USE_DATES` is off, so an opted-out date column is not reported only as free text.
